# Implementation decisions

- The repository contained only `spec.md`. The Git root is `C:\Users\SANJEEVA`, with unrelated pre-existing dirty/untracked state. All project files are confined to `OneDrive/Desktop/AI Mystery room`.
- `docs/SPEC.md` is a verbatim copy of the provided SSOT. The original is retained.
- MongoDB is the durable store. Leave `MONGODB_URI` empty for explicit in-memory fixture development; only an unavailable loopback URI may fall back in development. A failing remote URI is a startup error, avoiding hidden loss of persistence. Production refuses to start without MongoDB.
- Gemini is configured only on the server. Without `GEMINI_API_KEY`, the app uses the deterministic fictional fixture, clearly labeled fictional. No image generation provider is configured; image evidence is therefore not generated by Gemini.
- Access uses a 192-bit random public case ID plus a separate 256-bit bearer token. Only a SHA-256 hash is stored. The bearer token is shown once and stored in browser local storage for refresh resume.
- Generated cases currently receive structural and reference validation, with one repair attempt. Semantic fairness still requires human-reviewed fixtures; deterministic code cannot prove narrative fairness.
- Generation is stored as `generating`, `ready`, or `failed`; an explicit one-time retry is available, and interrupted database jobs older than two minutes are marked failed on startup. The API returns only safe stages while generating.
- The configured MongoDB URI was tested without printing it; MongoDB Atlas rejected authentication (code 8000 / `AtlasError`). The server now fails startup for that remote URI instead of silently using memory.
- The configured Gemini model/key passed a model metadata request, but two end-to-end case generation attempts timed out at 45 and 90 seconds. The generation budget is configurable; successful case generation is not claimed until a real case reaches `ready`.
